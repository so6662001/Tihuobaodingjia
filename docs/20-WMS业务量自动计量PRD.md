# 库准 WMS · 业务量自动计量 PRD

> **优先级**：**P0**（v2.2 套餐能否落地的唯一前置条件）  
> **业务方**：营销总裁 / 销售运营 / 财务  
> **产品方**：WMS 产品经理 + 计费平台研发  
> **本文件用途**：定义"按业务量四档收费"所需的**业务量统计 + 计费 + 账单 + 升级 + 超额叠加**完整产品方案  
> **目标节奏**：在 v2.2 套餐正式上线前完成最小可用版本（MVP）  
> **写作前提**：钢贸客户对"账单"敏感度极高，必须**透明、可对账、可争议、可申诉**

---

## 一、产品目标

让 v2.2 推出的"WMS 按业务量四档"在产品/财务/法务层面**真正能跑起来**——包含但不限于：

1. **每月自动统计** 客户业务量（入库 + 出库 + 移库 + 盘点单数）
2. **自动判档**：客户当前用量对应入门 / 标准 / 专业 / 集团 哪一档
3. **自动生成月度账单**：含本月单数明细、套餐内额度、超额单数、应付金额
4. **超额叠加**：超出套餐月额度按 ¥0.2/单累计；连续 3 个月超 → 自动建议升级
5. **客户自助看板**：客户随时可查"本月已用 X 单 / 套餐上限 Y 单 / 是否将超限"
6. **争议申诉流程**：客户对账单有异议时的标准处理路径
7. **销售/CSM 后台**：销售可看自己客户的用量趋势、风险预警、升级建议
8. **财务系统对接**：账单数据 T+1 同步到财务 ERP，自动开票

## 二、用户故事（核心 5 个角色）

### 2.1 客户老板
- 我想随时看"我现在用了多少单"
- 我不想被偷偷超额收费
- 我希望快超的时候系统提前提醒
- 我希望对账单有异议时有人 24h 内回复

### 2.2 客户仓管员
- 我的扫码、入库、出库、盘点动作不应该被"额外操作"打断
- 系统应该在后台自动统计，不影响我干活

### 2.3 公司销售（BD）
- 我要看到我的客户离套餐上限还差多少
- 客户快超时我要被提醒，**主动联系客户谈升档**
- 我要在 CRM 里清晰看到每个客户的预期续费档位

### 2.4 公司客户成功（CSM/KAM）
- 我要每月给客户出"用量小结 + 升档建议"报告
- 客户连续 3 个月超额，我要触发"自动升级"流程

### 2.5 公司财务
- 月底自动生成全部客户账单
- 异议账单自动隔离，正常账单自动发起开票流程
- 与 ERP 对账数据 100% 一致

## 三、业务量定义（**最关键，必须无歧义**）

### 3.1 计量定义

**"月度业务量单数" = 入库单数 + 出库单数 + 移库单数 + 盘点单数**

| 类型 | 触发条件 | 一笔的判定 |
|---|---|---|
| **入库单** | 系统中点击"入库确认" | 一张入库单 = 1 单（不论多少行/多少 SKU/多少吨）|
| **出库单** | 系统中点击"出库确认" | 同上 |
| **移库单** | 系统中点击"移库确认" | 同上 |
| **盘点单** | 系统中点击"盘点结束" | 同上 |
| 撤销 / 退回单 | 系统中撤销已确认单据 | **不扣减**（防止刷量）|
| 草稿 / 未确认 | 仅保存未确认 | **不计** |

### 3.2 边界情况

| 场景 | 处理 |
|---|---|
| 一张出库单分批装车 → 系统产生多张子单 | **按子单分别计费** |
| 一张入库单跨多个仓库 | 按"主仓"计 1 单 |
| 移库（A 仓 → B 仓）| **计 1 单**（移库单本身）|
| 盘点（仓库整体）| 1 次盘点 = 1 单（无论 SKU 多少）|
| 修改已确认单据 | **不重复计费** |
| API/导入批量生成 | 按生成的单数全部计费 |

### 3.3 业务量与套餐档对照（**销售必背**）

| 套餐 | 月单数上限 | 用户上限 | 仓库上限 | 超额单价 |
|---|---|---|---|---|
| 入门版 ¥4,800/年 | 3,000 单 | 5 | 1 | ¥0.2/单 |
| 标准版 ¥12,800/年 | 8,000 单 | 12 | 3 | ¥0.2/单 |
| 专业版 ¥28,000/年 | 25,000 单 | 30 | 7 | ¥0.2/单 |
| 集团版 ¥58,000/年+ | 无限 | 无限 | 无限 | — |

## 四、产品功能需求（按 P0 / P1 / P2 排期）

### 4.1 P0（v2.2 上线**必须**有）

#### F1 · 业务量计量引擎
- 后端服务实时监听单据"已确认"事件
- 写入计量日志表（含 deal_id / type / created_at / customer_id / warehouse_id）
- 计量数据保留 ≥ 5 年（供回溯）
- 每天 T+0 凌晨聚合到"月度业务量汇总表"

#### F2 · 客户用量看板（WMS 客户后台）
- 进入 WMS → 首页一眼可见"本月已用 X 单 / 套餐上限 Y 单 / 已用率 Z%"
- 用量柱状图（最近 12 个月对比）
- 距月底还有 N 天 → "按当前节奏预计本月共 ___ 单 → 超限 / 在线"
- 超额提醒：达 70% 黄色提醒 / 90% 红色提醒 + 销售同步收推送

#### F3 · 月度账单自动生成
- 每月 1 日 00:00 生成上月账单
- 账单内容：基础套餐费（按月摊销）+ 超额单数 × ¥0.2
- 推送渠道：客户后台 + 邮件 + 短信
- 账单 PDF 可下载（含明细，每一单的 ID 与时间戳，便于核对）

#### F4 · 销售/CSM 后台
- 自己负责客户的"业务量趋势 + 当前档位 + 距上限差距 + 升档建议"
- 客户连续 3 个月超 → CRM 自动建任务"升档商谈"

### 4.2 P1（v2.2 上线后 1 个月内补齐）

#### F5 · 自动升档建议
- 客户连续 3 个月业务量 > 当前档位 80%：
  - 系统推送"升档可省 ¥XX/月"建议
  - 触发销售/CSM 任务

#### F6 · 客户异议申诉流程
- 客户在账单页面点"异议" → 选原因（数据错误/重复计费/不应计费/其他）
- 异议进入工单系统 → CSM 5 工作日内复核
- 异议处理结果分：成立（红冲）/ 不成立（解释）/ 部分成立

#### F7 · 多客户聚合视图（集团客户）
- 集团客户（多个子公司账户）：母账户可看子公司聚合用量
- 集团版套餐自动按聚合判档

### 4.3 P2（v2.2 上线后 3 个月内）

#### F8 · 智能预测引擎
- 基于历史数据，预测客户未来 3 个月业务量
- 提前 90 天给销售"客户可能升档"线索

#### F9 · 按业务量阶梯优惠
- 客户用量大但稳定（如月 7,500 单稳定）→ 自动建议买更大套餐享更低单价
- 可生成"如果您升级到专业版，单价从 ¥1.6/单 → ¥1.12/单"对比图

#### F10 · 多语言 / 多币种
- 仅集团客户/海外客户使用
- 与 ERP 共用主数据

## 五、数据模型（产品/研发参考）

### 5.1 关键表

```sql
-- 业务量明细表（事件流）
CREATE TABLE wms_business_event (
  id BIGINT PRIMARY KEY,
  customer_id VARCHAR(64),
  warehouse_id VARCHAR(64),
  event_type ENUM('IN','OUT','TRANSFER','INVENTORY'),
  deal_id VARCHAR(64),  -- 关联具体业务单据
  occurred_at DATETIME,
  is_revoked BOOLEAN DEFAULT FALSE,  -- 撤销标记
  created_at DATETIME
) PARTITION BY RANGE (UNIX_TIMESTAMP(occurred_at));

-- 月度汇总表（账单依据）
CREATE TABLE wms_monthly_summary (
  customer_id VARCHAR(64),
  month_yyyymm VARCHAR(6),
  in_count INT,
  out_count INT,
  transfer_count INT,
  inventory_count INT,
  total_count INT,  -- 不含撤销
  package_tier ENUM('ENTRY','STANDARD','PRO','GROUP'),
  package_limit INT,
  excess_count INT,  -- 超出额度数
  excess_amount DECIMAL(10,2),
  base_amount DECIMAL(10,2),  -- 套餐基础月费
  total_amount DECIMAL(10,2),
  status ENUM('PENDING','CONFIRMED','DISPUTED','PAID'),
  PRIMARY KEY(customer_id, month_yyyymm)
);

-- 套餐配置表
CREATE TABLE wms_package_config (
  tier_code ENUM('ENTRY','STANDARD','PRO','GROUP') PRIMARY KEY,
  monthly_limit INT,
  user_limit INT,
  warehouse_limit INT,
  annual_price DECIMAL(10,2),
  excess_unit_price DECIMAL(10,2)
);

-- 异议工单表
CREATE TABLE wms_billing_dispute (
  id BIGINT PRIMARY KEY,
  summary_id BIGINT,
  customer_id VARCHAR(64),
  reason_code VARCHAR(32),
  reason_desc TEXT,
  submitted_at DATETIME,
  resolved_at DATETIME,
  resolution_type ENUM('ACCEPTED','REJECTED','PARTIAL'),
  adjustment_amount DECIMAL(10,2)
);
```

### 5.2 关键接口

| API | 方法 | 用途 |

## 七、合规与法务

### 7.1 合同条款必含（与法务对齐）

- 业务量定义（与本 PRD 第三章一致）
- 套餐内额度与超额单价
- 撤销单不计费的明确说明
- 账单异议申诉流程与时限
- 数据保留期 ≥ 5 年
- 客户随时可全量导出业务量数据

### 7.2 反作弊
- 同一单据撤销后重开 → 仅算 1 次
- 异常单据爆发（如 1 分钟 1,000 单）→ 自动隔离待人工审
- 撤销率 > 30% 的客户 → 风控复核

### 7.3 透明承诺
- 账单可追溯到具体单据（点击账单中的"超额 N 单"可看到是哪 N 单）
- 客户随时可全量下载用量明细（CSV/Excel）

## 十一、风险与对冲

| 风险 | 影响 | 对冲 |
|---|---|---|
| 业务量定义客户不接受 | 拒签 | 销售用本 PRD 第三章话术 + 透明账单 |
| 撤销率高客户钻空子 | 损失 | 撤销率 > 30% 触发风控 |
| 账单争议大批量爆发 | 公关 | 异议申诉 SOP + CSM 主动复核 |
| 销售错误建议升档 → 客户反感 | 流失 | 升档建议必须基于 3 个月数据 |
| 计量系统宕机 | 客户不信任 | 双地域容灾 + 历史可回溯 |
| 价格上限被客户用爆 → 不知所措 | 服务 | 集团版 ¥58,000+ 提供"超大无限"兜底 |

> 这个 PRD 的优先级 = WMS 产品总监一切其他工作的总和。
